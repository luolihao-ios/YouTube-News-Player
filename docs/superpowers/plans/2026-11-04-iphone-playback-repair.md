# iPhone 播放验证循环与播放页修复

## 用户实测与已确认事实

- 用户测试 TestFlight 1.0（8），iPhone 的 YouTube 官方播放器显示“请登录，以便我们确认你不是聊天机器人”，外层显示频道禁止内嵌。
- 原实现每个播放器创建非持久 WebKit 数据，并把所有点击链接和新窗口交给外部浏览器；Safari 登录不会为独立 WKWebView 建立同一个会话，外跳后返回不能修复本次播放器。
- 原 iOS、macOS、visionOS 根视图都通过 sheet 显示播放页，与用户要求的完整页面不符。
- 2026-11-04 重新查询首页三个频道的真实 Data API：频道身份正常，各有可嵌入公开直播。API 标识不能证明当前网络下的官方播放器一定放行。

## 本次实现

1. 保留官方 IFrame Player、控件、广告和用户点击播放；不提取媒体、不修改浏览器身份、不代理请求或绕过 YouTube 验证。
2. 用户同意后，频道共用本 App 的持久 WebKit 数据；设置可清除。用有明确 HTTPS App 身份与 Referer 的模拟页面请求加载本地播放器。
3. 认证导航不给外部浏览器自动开启登录循环。外部观看只由用户明确选择；错误码、导航决策、加载与播放状态自动写本机诊断。
4. iPhone 播放页完整覆盖首页；Mac/Vision Pro 在同一窗口切换完整播放页。退出和换台暂停旧播放。
5. 101/150 显示本次官方内嵌播放被拒绝及可能原因，保留实际码；不把所有拒绝一概解释为频道设置。
6. 诊断位于 Documents/PlaybackLogs，限制大小和备份，不写 Cookie、帐号、API Key、Token 或完整请求；设置与错误区可导出。
7. iPhone 错误区提供用户主动选择的系统 Safari 网页备用入口，完整覆盖页面；验证与观看留在同一个系统浏览组件内，不自动外跳，不把该组件的帐号 Cookie 搬回 WKWebView，不声称完成验证后内嵌播放必然恢复。

## 验证

- 导航策略覆盖认证地址、伪装域名、子框架、用户点击和脚本新窗；日志覆盖实际文件、轮转、清除与敏感字段过滤。
- 使用真实播放器脚本的 Node 回归、完整 Python 回归、Swift XCTest 和三平台编译验证。
- Apple VALID 只证明构建可处理。YouTube 验证是否解除，需要用户实际 iPhone 网络复测；若仍拦截，使用新版本自动保存的原始诊断，不声称浏览器登录后即可解决。
