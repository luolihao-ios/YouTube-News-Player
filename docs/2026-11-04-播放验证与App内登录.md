# 播放排查与 App 内登录观看

## 已核实的故障

- 用户提供的 iPhone 1.0（10）日志中，6 次尝试均成功加载 IFrame API 并携带 Referer，6 次实际播放均返回 150；没有进入播放状态 1。
- 不能将此情况直接判断为频道关闭内嵌：相应两场 TVBS 直播的公开 Data API 状态均允许内嵌。
- GitHub 实际 WebKit 对照运行 41786906883：原有本地 HTML 方案返回内嵌错误；官方直接加载方案显示登录验证。两场直播均无视频时间推进。此结果仅覆盖 runner 的 macOS 与网络，不能代表用户手机网络。
- 上述证据不支持宣称内嵌播放已经修复，也不支持将播放器 ready 当作实际播放。

## 本次 iPhone 实现

1. 可正常内嵌的直播继续在原生详情页中播放。
2. 遇到 101、150 或实际 Google 登录导航时，暂停并移除原有播放器，只转入一次 App 内的系统全屏 YouTube 观看页面。
3. 使用 SFSafariViewController，由用户在官方网页中输入账户并完成验证；验证后继续留在同一个网页观看。App 不读账户、Cookie、密码、页面内容，也不复制会话。
4. 关闭系统页面后返回频道详情，不重试未登录的 IFrame、不自动再次弹出。页面只保留一个“在 App 内继续观看”入口，用户可主动重新打开。
5. 仅页面初始加载与打开/关闭事件写入原有文件日志；系统页面未暴露登录成功或播放状态，因此这些事件不能作为登录、播放成功证据。

本次新增登录观看路径仅用于 iPhone/iPad。macOS、visionOS 继续原有原生页面，不声称已实现相同的系统登录路径。

## 规则与验证范围

- Google 支持通过 iOS SFSafariViewController 打开第三方普通网页；嵌入式 WKWebView 不支持 Google 用户登录。
- https://developers.google.com/identity/siwg/supported-browsers
- https://developers.googleblog.com/en/upcoming-security-changes-to-googles-oauth-20-authorization-endpoint-in-embedded-webviews/
- https://developer.apple.com/documentation/safariservices/sfsafariviewcontroller/

自动回归覆盖：相同视频只自动转入一次、关闭后不再转入、不返回 IFrame、手动重新打开、不同视频目标隔离、无关错误不请求登录、非法视频 ID 拒绝打开。

仍须真机验收：进入失败频道后是否出现 App 内全屏官方网页、能否在该页面登录、登录后同页是否实际出画面和声音，以及关闭后无重复弹出和后台重叠声音。编译、网页打开、上传及 Apple 处理完成均不能代替此项验收。
