# 三平台商店与签名操作

## 同一应用、三个二进制
三平台使用同一个 App Store Connect App 记录和 `com.luolihao.newslive`。名称统一 `YouTubeNewsLive`，iOS、macOS、visionOS 分别构建上传。tvOS 已取消，不为它更新版本本地化、上传截图或二进制，不删除已有草稿。

Apple 的 AppInfo 名称、副标题是整个 App 共用资料，而各平台版本说明分开。脚本只选择唯一可编辑 AppInfo，统一写入 en-US、zh-Hans、zh-Hant 名称、副标题；然后按明确平台筛选唯一可编辑的 AppStoreVersion，写入说明、关键词、宣传文字并逐字段回读。所有选定平台都通过预检后才开始写入。不填写未经提供的支持/隐私 URL，不生成或上传概念截图，不提交审核、不发布。

## 工作流入口
`.github/workflows/ios-testflight.yml` 提供：

- `operation=inspect` 或 `prepare`：纯 GET，读取 App ID、Bundle 资源及其平台、全部平台版本与语言、builds；不创建或修改 Apple 资源。
- `operation=metadata`：填写并回读指定三平台或其中一个的三语言商店文字。
- `operation=release`：先完成共用构建验证与商店准备，再并行签名上传选定平台；单个平台失败不取消其他平台。
- `platform=all|ios|macos|visionos`；all 不含 tvOS。

默认只读 inspect。报告在工作流附件 `YouTubeNewsLive-Apple-商店报告` 中。上传后需单独再次 inspect 核对 Apple 处理结果；命令成功不等于 TestFlight 可用。按用户要求，不在本地轮询等待 GitHub 出包。

```powershell
gh workflow run ios-testflight.yml -f operation=inspect -f platform=all
gh workflow run ios-testflight.yml -f operation=metadata -f platform=all
gh workflow run ios-testflight.yml -f operation=release -f platform=ios
```

## 独立关联已上传构建

如果上传运行使用旧工作流，或需要重试关联，可以运行 `attach-builds.yml`，不会重新构建或上传。必须明确填写本次实际构建号。它核对同一 App、构建号、平台和营销版本，只关联有效构建并回读商店版本关系，不提交审核。

可选 `release_run_id` 让 GitHub 先等待同仓库 `ios-testflight.yml` 的确切数字运行 ID 结束，等待任务最多 90 分钟；即使发布运行部分平台失败，也在确认整个运行 `completed` 后检查各平台实际结果。未提供时直接开始 Apple 处理检查。目标运行必须属于本仓库及指定工作流，否则失败。此等待发生在 GitHub，不需要本机持续轮询。

```powershell
gh workflow run attach-builds.yml -f build_number=4 -f platform=all -f release_run_id=41727934122
```

发布运行结束后，每个平台再独立按 30 秒间隔等待 Apple 处理，最多 900 秒。缺失、超时、无效、过期、跨平台或重复匹配均明确失败并保留报告；已关联同一构建时不重复写入。独立关联流程使用 `youtubenewslive-build-attachment` 并发组。

## 证书和隔离边界
仅在 GitHub 仓库 Secrets 使用 Apple API 私钥、发行 P12。原有 Secret 保持不变：`APP_STORE_CONNECT_API_KEY_ID`、`APP_STORE_CONNECT_ISSUER_ID`、`APP_STORE_CONNECT_API_KEY_BASE64`、`IOS_SIGNING_CERTIFICATE_BASE64`、`IOS_SIGNING_CERTIFICATE_PASSWORD`、`YOUTUBE_API_KEY`。临时钥匙串使用随机密码，不需要更改已有钥匙串 Secret。

Apple Distribution 官方支持 macOS App 签名，因此现有通用发行证书可以复用，仍需运行时比对本团队 API 证书的 DER 指纹与有效期。旧式 iOS Distribution 不允许用于 macOS 或 visionOS。macOS 安装包还需要独立 Mac Installer Distribution 证书和私钥，必须提供 `MAC_INSTALLER_P12_BASE64`、`MAC_INSTALLER_P12_PASSWORD`；缺少时 Mac 任务在执行任何外部命令前明确失败，不会创建或撤销证书。

BundleId 的平台枚举与商店版本平台不同。BundleId 只有 `IOS`、`MAC_OS`、`UNIVERSAL`；若当前 Bundle 平台不支持目标，脚本明确失败并要求在开发者后台核对本 App ID，不猜测 `VISION_OS` BundleId 平台或注册另一个 App。描述文件严格绑定当前 Bundle 资源、平台类型、有效期和唯一发行证书；已有匹配文件优先复用，只有没有匹配文件时才创建本项目专属描述文件。iOS/visionOS 使用 `IOS_APP_STORE`，原生 Mac 使用 `MAC_APP_STORE`。

macOS 任务检查 SDK、P12、描述文件，手动签名归档并导出 `.pkg`，验证 App 身份与包签名；iOS/visionOS 各自导出 `.ipa`，检查成品名称、Bundle、版本和运行配置。所有平台交给 Xcode 按归档平台上传，不猜测 altool 平台参数。日志和报告不得包含 API Key、私钥、密码或 P12 原文。

## 本地验证与证据边界

```powershell
python -m unittest discover -s tests -p 'test_*.py'
```

本地单元测试覆盖只读行为、取消 tvOS、平台草稿唯一性、已发布版本保护、写入回读、发行证书类型、缺少 Mac 安装证书、描述文件证书与 Bundle 隔离、成品身份。Windows 无法代替 Xcode、Apple 上传和设备播放验证，必须以实际工作流与 Apple 回读为准。

## Apple 官方依据

- [证书类型](https://developer.apple.com/help/account/certificates/certificates-overview)：Apple Distribution 支持各平台，Mac Installer Distribution 用于 Mac App Store 安装包。
- [App Store 描述文件](https://developer.apple.com/help/account/provisioning-profiles/create-an-app-store-provisioning-profile)：iOS、iPadOS、visionOS、watchOS 共用 App Store Connect 发行类型，macOS 单独。
- [BundleId 平台枚举](https://developer.apple.com/documentation/appstoreconnectapi/get-v1-bundleids)：IOS、MAC_OS、UNIVERSAL。
- [商店版本平台枚举](https://developer.apple.com/documentation/appstoreconnectapi/get-v1-apps-_id_-appstoreversions)：IOS、MAC_OS、TV_OS、VISION_OS。
- [上传与 Apple 处理](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds)：二进制上传后仍需 Apple 处理才出现在 App Store Connect。
